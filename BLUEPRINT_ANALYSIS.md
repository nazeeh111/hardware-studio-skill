# Blueprint.io public product analysis

Observed on 22 October 2026 through the live, public website and a fresh, unauthenticated Chrome session captured with Reverse Engineer Anything (REA). This is an analysis of visible behavior and publicly shipped frontend code, not access to Blueprint's private backend or an endorsement. No account was created, no design credit was used, and no purchase was made.

## Blueprint's published feature and plan statements

The [FAQ](https://www.blueprint.io/faq) says a prompt can produce a bill of materials, sourcing links, wiring diagram, build instructions and a 3D mechanical render. It says a design may ask follow-up questions, supports image and sketch references, keeps projects private by default, and can publish them separately. It describes CAD generation with STL, STEP and GLB downloads, version history, and a project ZIP export on Pro and Ultra. It also says there is no public API or manufacturing service at present.

The [pricing page](https://www.blueprint.io/pricing) lists a free Basic tier with design and CAD credit limits, and paid tiers with more generation capacity. These are live page statements that can change, not commitments replicated by this repository.

The FAQ acknowledges that parts, prices, placement and Amazon links may be wrong or region-specific. It recommends checking a design before buying or building. This limitation materially shaped Hardware Studio: it exposes unknowns and review marks rather than labeling its concept output build-ready.

Static inspection of the captured [main frontend bundle](https://www.blueprint.io/assets/index-Bce6DG7-.js) found request-code references to generation runs, uploaded input images, project saves, part canonicalization and sourcing, wiring-rail inference, CAD jobs and part questions, project ZIP export, publishing, and collaboration. The references show planned client/server boundaries in this shipped version. They do **not** prove that any endpoint is available to an unauthenticated visitor, how its backend works, or that a generation succeeds. REA's first-party JavaScript graph (`ev_dcf3f3fe5a06ee4ba4aead54727958a15449a7ba547abf965dd2b3ebe5a7dfa1`) parsed three served scripts but hit a heap limit while building semantic relationships for the 4.6 MB main bundle, so graph coverage is partial. The captured event stream also ended with some requests unfinished. No Blueprint code or assets are reused in Hardware Studio.

A second unauthenticated REA capture of the [public 3D printer project](https://www.blueprint.io/s/4HKdHznzhy-I8Gfv61LL0FATpp_CxnKSKkiFw8hQCFw) retained its public project response (`ev_b842d174cff7437272974f02621cf59108b87bf5778b084082609644d92bd737`). That one response contained 48 part or assembly nodes, 24 electrical relationships, 40 mechanical relationships, and four instruction phases with 26 substeps total. Electrical relationships named source and target nodes, a type and voltage; node records also contained pin lists, dimensions as text, cost estimates and sourcing fields. This is a response-shape observation for one published project, not evidence that each link maps exact pins or that its dimensions and prices are correct. The project's content is not copied into this repository.

A closer read of that retained response found `partIds` on individual instruction substeps and separate tool and assumption lists in the instruction preamble. All 24 sampled electrical relationships linked valid part nodes. **15 of 24** also named both exact pin endpoints; five of those 30 named endpoints were absent from the corresponding node's listed pin names. That is a data-consistency finding, not proof that the intended wiring is wrong, because the node lists may be incomplete or use aliases. One of 40 sampled mechanical relationships linked a part ID to itself, which may represent multiple units but does not by itself specify a physical joint. Hardware Studio records optional part-linked build steps and explicit project tools/assumptions, and flags broken step references on import or later edits; it does not copy the sampled instructions.

## Inferred workflow, with uncertainty

The visible product sequence suggests: idea or reference → clarifying questions and generation → project record → parts and sourcing → connection graph → mechanical visualization or CAD → instructions → revision or publication. That sequence is an inference from the interface, FAQ and shipped frontend references. The model orchestration, private backend data schema, CAD generation method, supplier search process, validation logic, security controls and private account flow were not established.

## Reimplementation decisions

Hardware Studio is intentionally original. It uses two editable, hand-authored starter structures and a local data model so its difficult mechanism, coordinated parts/connections/steps and review state, can be exercised without a billed model API. It asks up to four deterministic follow-up questions after an idea is entered, always including an observable success check; answers and open questions are included in the saved brief and optional local-model prompt. This is a transparent intake aid, not evidence of Blueprint's private question logic. An optional local Ollama model can draft other ideas, with generated prices and verification marks cleared before saving. A sketch or photo can be resized and retained locally with a project; models reporting vision support can receive that image for drafting, but interpretation remains unverified. It adds reference integrity checks, optional exact pin or terminal fields with missing-endpoint review, separate linked mechanical mounting notes, a part-linked power-budget worksheet, specification links with check dates, local revision history, a self-contained export of its browser data and conceptual diagrams, visible uncertainty, and reset review marks after import or restoration. Data stays in the browser. Its component index is conceptual. A separate, manually authored [Pico + NeoPixel tray example](examples/pico-neopixel-tray/README.md) includes dimensioned CAD, a manufacturer-model fit report and a provisional, source-backed electrical path; the supply and physical checks remain open. A local tray workbench can also generate one constrained class of rectangular tray CAD and compare user-supplied STEP solids at explicit placements; it does not infer an arbitrary assembly or prove physical fit. Hardware Studio does not match Blueprint's AI quality, live sourcing, account system, collaboration, publishing, payments or manufacturing. The companion skill explains how to reach a validated design through independent sources and suitable engineering tools.

Do not treat a polished render as manufacturing proof.
